# Feature 002：多图与封面

状态：实现完成，待设备验收
依赖：Feature 001
上游：[PRD](../../product/卡迹App_PRD_v1.0.md)
详细设计：[Feature 002 设计](../../superpowers/specs/2026-07-28-feature-002-multi-image-management-design.md)

## 1. 用户结果

用户可在建卡时一次选择多张图片，也可在详情中继续追加；每张图可标记为正面、背面、包装、编号、细节或其他，图片顺序与封面可独立调整，重启后结果保持一致。

## 2. 范围内

- 系统相册多选与逐次追加；
- 单藏品最多 20 张受管图片；
- 六种图片用途、稳定排序和唯一封面；
- 详情图集、设为封面、调整用途、前移/后移；
- 删除影响提示，以及“保留原图”或“同时删除原图”；
- schema v1 到 v2 无损迁移；
- 批量导入失败补偿、孤儿文件清理和重启一致性。

## 3. 范围外

相机、连续拍摄、裁切、增强、缩略图生成、OCR、边缘识别和模板输出属于 Feature 009。跨藏品共享同一原图、回收站恢复已移除图片和云同步不在本 Feature。

## 4. 规则

- 第一张图片默认 `front` 且为封面；其余默认 `other`。
- 图片顺序使用连续的 `0..n-1`；封面不要求排在第一位。
- 同一藏品始终恰有一个活跃封面；删除封面后由剩余顺序第一张接任。
- 不允许删除最后一张活跃图片，以满足 BR-IMG-002。
- 删除默认保留原图：图片记录软删除，启动清理仍视为有引用。
- 选择“同时删除原图”时删除图片记录和文件；文件删除失败留下的孤儿由下次启动重试。
- 原图只读；`derivedRelativePath` 为后续 Feature 009 预留，不覆盖原图。
- 多图导入全部成功后才写库；任一文件或事务失败会补偿本批次已导入文件。
