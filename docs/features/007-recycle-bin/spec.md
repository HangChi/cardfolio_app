# Feature 007 规格

## 1. 目标

卡片删除后先进入回收站，可完整恢复或经二次确认永久删除；收藏列表、首页统计、套卡完成度和购买目标选择必须使用同一套“仅活跃卡片”口径。

## 2. 范围

- 卡片藏品实例软删除与恢复；
- 回收站列表、永久删除影响预览和二次确认；
- 7、30、90 天保留期配置，默认 30 天；
- 启动时自动清理超过保留期的卡片；
- 永久删除卡片图片元数据和受管文件；
- 文件清理失败后的持久化重试队列。

## 3. 范围外

标签、系列、套卡、购买记录自身的独立回收站，跨设备同步，操作历史，多选批量操作和系统级后台定时任务不在本次范围。

## 4. 级联、保留与恢复矩阵

| 对象 | 软删除 | 恢复 | 永久删除 |
|---|---|---|---|
| `card_items` | 写入 `deletedAt` | 清空 `deletedAt` | 删除根行 |
| `card_definitions` | 保留 | 无需修改 | 保留，避免破坏套卡款式、标签、系列和其他藏品 |
| `card_images` | 保留且继续计入文件引用 | 原样可见 | 删除行，原图与派生图加入文件清理队列 |
| `card_tags` / `series_cards` / 自定义字段值 | 保留 | 原样恢复 | 随定义保留 |
| `card_set_members` | 保留；完成度查询忽略已删除藏品 | 原样恢复进度 | 保留预期款式 |
| `purchase_items` | 保留快照；新购买目标不可选已删除卡片 | 原样恢复 | 删除指向该藏品的目标；不删除购买账本 |

## 5. 查询口径

普通收藏、详情、筛选、统计、套卡拥有量和购买目标都要求 `card_items.deleted_at IS NULL`。回收站是唯一读取 `deleted_at IS NOT NULL` 的产品入口。软删除和恢复必须触发现有 Drift 响应流重新计算。

## 6. 永久删除与文件一致性

永久删除在单个数据库事务内把所有原图和派生图相对路径写入 `file_cleanup_queue`，再删除图片、购买目标和卡片行。事务提交后尽力清理文件；单个文件删除成功后移除对应队列项，失败项保留并在下次启动重试。文件不存在视为成功。

## 7. 保留期

保留期存储在数据库单例设置中，仅允许 7、30、90 天。到期判断为 `deletedAt <= nowUtc - retentionDays`。应用启动时执行一次自动清理；不依赖移动平台后台调度。

## 8. 需求追踪

- FR-DATA-003；
- BR-DEL-001..002；
- 相关 BR-SET、BR-IMG；
- NFR-DATA-001；
- AC-P0-007。

## 9. 完成定义

九件套、数据库迁移、领域/仓储、回收站页面、详情删除入口、启动恢复和自动清理完成；数据库、仓储、Widget、迁移自动化以及静态分析通过；模拟器步骤列出但不伪报执行。
