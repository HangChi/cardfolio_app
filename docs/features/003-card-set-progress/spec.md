# Feature 003：套卡与完成度

状态：实施中
依赖：Feature 001、Feature 002
上游：[PRD](../../product/卡迹App_PRD_v1.0.md)
详细设计：[Feature 003 设计](../../superpowers/specs/2026-07-28-feature-003-card-set-progress-design.md)

## 1. 用户结果

用户可创建和编辑套卡，设置已知或未知总数、发行信息和备注；可把已有卡片款式或尚未拥有的预期款式加入套卡，并管理成员编号、顺序、必需性和套卡封面。套卡详情始终从当前数据计算已拥有、缺失、重复和完成状态。

## 2. 范围内

- 套卡创建、编辑、列表和详情；
- 已知/未知预计成员数；
- 关联已有卡片款式和创建未拥有成员；
- 成员编号、必需/可选、排序、移除；
- 从已拥有成员图片选择套卡封面；
- schema v2 到 v3 无损迁移；
- 卡片软删除/恢复后的实时进度重算。

## 3. 范围外

系列、标签与筛选属于 Feature 004；购买整套与成本属于 Feature 005；首页/统计聚合属于 Feature 006；回收站 UI 和套卡删除/恢复属于 Feature 007；套卡连续拍摄属于 Feature 009。

## 4. 规则

- 同一款式在同一套卡中最多一个活跃成员关系。
- 未拥有成员由没有活跃 `CardItem` 的 `CardDefinition` 表达，不使用虚构数量。
- 必需成员分母为活跃且 `required=true` 的不同成员款式数；已拥有分子要求至少一个未删除且数量大于 0 的藏品实例。
- 重复数量按同款式全部活跃藏品的 `quantity` 之和计算，数量大于 1 标记为重复，但完成度只增加 1。
- `countKnown=false` 时 `expectedCount` 必须为空，只显示已拥有款式数，不显示百分比或集齐状态。
- `countKnown=true` 时预计成员数至少为 1，且不得小于当前活跃成员数。
- 套卡封面只能引用该套卡当前已拥有成员的活跃图片；成员移除或图片失效时查询回退为空。
- 完成度只在查询时计算，不持久化派生百分比。
