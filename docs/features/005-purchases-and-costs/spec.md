# Feature 005：购买记录与累计花费

状态：实施中
依赖：Feature 001、Feature 003
上游：[PRD](../../product/卡迹App_PRD_v1.0.md)
详细设计：[Feature 005 设计](../../superpowers/specs/2026-07-28-feature-005-purchases-and-costs-design.md)

## 1. 用户结果

用户可为实际购入的卡片或套卡记录付款事实，查看可追溯的累计花费，并通过分摊了解一笔多对象购买的归因，而不会重复累计。

## 2. 范围内

- 购买日期、商品金额、ISO 币种、渠道、卖家、运费、手续费和备注；
- 一笔购买关联一个或多个卡片藏品或套卡；
- 可选完整分摊、单卡购买和整套购买；
- 引用原购买的独立退款/调整；
- 原币种分组累计及运费/手续费口径切换；
- 汇率的精确比率、来源和获取时间存储边界；
- 购买历史、创建表单、退款入口及按原币种的入手成本排序；
- schema v4 到 v5 无损迁移。

## 3. 范围外

主币种设置、自动联网获取汇率、统计图表和下钻属于 Feature 006；购买编辑/删除和回收站属于 Feature 007；导出导入属于 Feature 008；同步属于 Feature 010。

## 4. 规则

- 商品金额、运费和手续费均使用最小货币单位整数；普通购买三者不得为负。
- 默认累计金额是商品金额 + 运费 + 手续费；展示可分别排除运费、手续费。
- 购买必须至少关联一个活跃卡片藏品或套卡；同一目标不得重复。
- 启用分摊时每个目标都必须有非负分摊，合计必须等于默认累计金额。
- 分摊只用于目标归因，任何累计查询不得把分摊加到购买金额之上。
- 退款是独立调整，必须引用存在的普通购买、使用相同币种且金额为负；原购买不改写。
- 调整不复制购买项目；展示和归因通过原购买关系追溯。
- 多币种无有效换算时按币种分组，不能输出单一伪总额。
- 购买项目保存目标名称快照；目标后续软删除或永久删除不破坏购买审计。
- 发售价不属于购买事实，不进入累计。
- 卡片入手成本排序先按币种，再按该卡可归因金额；跨币种不直接比较数值。
