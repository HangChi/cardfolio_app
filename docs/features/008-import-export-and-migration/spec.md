# Feature 008 规格

## 1. 目标

用户可把全部逻辑数据、原图和派生图导出为可验证 ZIP，并在空收藏库或已有收藏库中
安全导入。任何损坏、不兼容或冲突必须在写入前被发现，失败不得改变现有数据。

## 2. 范围

- 格式版本 1 的 `manifest.json + data.json + images/...` ZIP；
- 全部 17 张业务表的逻辑字段、关系、精确金额、软删除状态和图片校验和；
- 导出内容/隐私说明、原生文件选择器、进度与取消；
- 空库恢复和“仅新增”合并；
- 导入影响预览、冲突列表和成功/失败报告；
- 当前格式版本兼容检查与逻辑格式前向迁移入口。

## 3. 范围外

CSV/相册字段映射、加密 ZIP、覆盖本地冲突、后台导入、云恢复、跨设备冲突副本和
数据库物理文件复制不在本次范围。

## 4. 格式与安全边界

- `formatVersion = 1`，支持范围为 `1..1`；数据库 schema 版本只作来源信息，
  不决定逻辑格式兼容性。
- ZIP 最多 50,000 个条目、2 GiB 总解压大小、64 MiB 单条目、100:1 压缩比。
- 路径必须是 `/` 分隔的规范相对路径；拒绝绝对路径、反斜杠、空段、`.`、`..`、
  符号链接、重复路径和未知根条目。
- 清单列出 `data.json` 与每个图片条目的字节数和 SHA-256；所有声明与实际必须一致。
- `manifest.json` 最大 2 MiB，`data.json` 最大 64 MiB。

## 5. 导出

数据库读取在一致性事务中完成，使用逻辑字段名构建快照；图片逐个验证存在、大小和
数据库 SHA-256。先在 App 临时目录生成 ZIP，成功后再复制到用户选择的目标文件。
取消或失败清理临时文件，绝不修改收藏库。

## 6. 导入与合并

导入先复制到 App 临时目录，再执行 ZIP 结构、限制、版本、清单、校验和、JSON 类型、
必填字段、UUID、关系、金额和图片引用验证。预览模式不写入。

- 空库恢复：目标 17 张业务表均为空，完整插入快照。
- 仅新增合并：本地不存在的 UUID/复合键可新增；内容完全相同的已有记录跳过；
  相同键但内容不同视为冲突并阻断确认，不静默覆盖。
- 写入按父表到子表顺序在单个数据库事务中执行。图片先写 staging；数据库事务成功后
  移入最终位置。文件提交失败时删除本次文件并回滚数据库事务。

## 7. 取消与报告

验证和文件复制按条目检查取消令牌；数据库提交开始后不可取消，以保持原子性。
报告包含模式、已新增/跳过实体数、图片数、冲突数和完成时间，不包含卡名、备注、
购买明细或绝对路径。

## 8. 需求追踪

FR-DATA-001..002、BR-IMG-001..003、BR-COST-001..006、
BR-SYNC-001..002、NFR-DATA-002..003、SEC-003..004、AC-P0-008。

## 9. 完成定义

九件套、格式实现、仓储、文件选择 UI、兼容迁移入口、全实体往返/安全/原子性/Widget
自动化和静态分析通过；模拟器步骤列出但不伪报执行。
