# 测试数据指南

## 1. 原则

- 只使用合成数据或明确授权的素材。
- 不把真实用户卡片、相册图片、账号或购买记录提交到仓库。
- 固定 ID 和时间用于可重复断言，随机数据必须记录种子。
- 每个测试自行创建并清理临时数据库与目录。

## 2. 标准数据集

| 数据集 | 内容 | 用途 |
|---|---|---|
| `empty` | 无记录 | 空状态 |
| `single-card` | 一定义、一藏品、一正面图 | Feature 001 主流程 |
| `duplicate-items` | 同定义下两份藏品 | 数量和去重边界 |
| `multi-image` | 正反面与多附图 | Feature 002 |
| `set-progress` | 完整、缺失、重复成员 | Feature 003 |
| `cost-history` | 多币种被拒、同币种多笔购买 | Feature 005 |
| `soft-deleted` | 活跃与已删除混合 | Feature 007 |
| `large-library` | 至少 10,000 个藏品元数据 | 容量与查询性能 |

## 3. 图片夹具

准备最小合法 JPEG、PNG、WebP、HEIC（平台支持时）、损坏文件、零字节文件、超大尺寸图片和方向信息图片。夹具不含 EXIF 位置和个人信息。文件名不用于业务判断。

## 4. 数据版本

每个已发布 schema 保留只读数据库夹具。迁移测试从旧夹具复制到临时目录后执行升级，再验证记录数、关系、图片引用和关键查询。旧夹具不在原位修改。

## 5. 清理

测试完成后关闭数据库句柄，再删除明确的临时目录。失败测试也必须在 teardown 中执行清理。设备端人工测试使用专用测试账号或本地数据，并在验收后通过 App 内清除数据或系统卸载清理。
