# 性能计划

## 1. 指标

| 场景 | 目标 | 测量方法 |
|---|---|---|
| 冷启动到可交互 | 中端 Android P95 ≤ 2.5 秒 | profile 构建，至少 20 次 |
| 收藏首屏查询 | 10,000 条元数据 P95 ≤ 300 ms | 数据层基准 |
| 列表滚动 | 主要滚动阶段不持续掉帧 | Flutter DevTools |
| 单图导入保存 | 常见 5 MB 图片 P95 ≤ 1.5 秒，不含系统选择器 | 端到端时间点 |
| 12MP 图片处理 | UI isolate 不连续阻塞超过 100ms；记录总耗时和峰值内存 | profile 真机、固定样本各 10 次 |
| 搜索响应 | 10,000 条数据 P95 ≤ 200 ms | 查询基准 |

PRD 的 NFR-PERF 和 NFR-CAP 是最终约束；本表为工程测量口径。

## 2. 策略

- 列表只查询摘要字段并分页/增量加载。
- 图片生成适合列表的缩略图，解码尺寸匹配显示尺寸。
- 校验和、复制和批量导入在非 UI 阻塞路径执行。
- 图片解码、透视、增强和编码在 worker isolate 执行；长边处理上限为 4096px。
- 为外键、排序、搜索和软删除条件建立基于查询证据的索引。
- 统计使用可测量的 SQL 聚合，避免在 UI 层遍历全量记录。

## 3. 基线与回归

每个发布候选版本在固定设备、固定数据集和 profile 模式运行。记录 Flutter 版本、设备、系统版本、数据量、构建号和结果。任一 P95 指标退化超过 15% 时阻断发布，除非有书面风险接受。

Feature 009 设备基准使用至少 10 张 12MP JPEG、3 张 HEIC、浅/深背景和倾斜卡面；
记录边缘建议是否需手动、处理总耗时、UI 卡顿、峰值内存和派生 JPEG 尺寸。

## 4. 容量

至少验证 10,000 个藏品、30,000 张图片引用和 50,000 条购买记录的启动、查询、导出和迁移。磁盘容量不足时必须在写入前失败，不留下半成品。
