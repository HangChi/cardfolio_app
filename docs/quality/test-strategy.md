# 测试策略

## 1. 目标

测试围绕“用户数据不丢失、核心流程可离线完成、版本升级可恢复”建立。每个 PRD 验收项必须映射到自动化测试或有记录的设备验收。

## 2. 测试层级

| 层级 | 关注点 | 工具/环境 |
|---|---|---|
| 单元测试 | 值对象、业务规则、状态机、错误映射 | `flutter_test` |
| 数据集成 | Drift 查询、事务、迁移、文件补偿 | 临时数据库与目录 |
| Widget | 页面状态、表单、导航、可访问性 | `flutter_test` + 依赖替身 |
| 端到端 | 相册、持久化、重启、关键流程 | Android 模拟器/真机 |
| 人工探索 | 权限、系统返回、极端设备和视觉 | 兼容性矩阵中的设备 |

## 3. 自动化规则

- 新行为先有失败测试，再实现。
- 测试不得依赖执行顺序、真实网络、用户相册或生产目录。
- 时间、ID、文件目录、仓储和平台插件通过契约注入。
- 数据库测试启用外键，并覆盖事务回滚。
- 异步 UI 测试等待明确状态，不使用任意时长睡眠。
- 修复缺陷时先添加可复现的回归测试。

## 4. 必测风险

- 快速重复保存只创建一份数据。
- 文件复制成功但数据库失败时完成补偿。
- 进程中断后启动清理无引用文件。
- 数据库迁移失败保留原数据库。
- 权限拒绝和选择器取消不产生脏数据。
- 软删除内容默认不出现在查询结果。
- 导入前验证兼容性，失败不修改现有数据。
- 同步冲突不覆盖不可恢复的本地修改。

## 5. 合并门禁

每个 PR 必须通过：

```powershell
dart format --output=none --set-exit-if-changed lib test integration_test
flutter analyze
flutter test
```

涉及平台插件时增加 Android 设备验收；涉及 schema 时增加从上一发布版本升级的迁移测试；涉及 UI 时增加目标节点的视觉与无障碍检查。

## 6. 发布门禁

- P0 验收项全部通过。
- 全量测试、迁移测试和 debug/release 构建通过。
- 崩溃、阻断错误和性能指标无未解释回归。
- 回滚路径、备份恢复和数据兼容性经过演练。
- 测试证据随版本归档。
