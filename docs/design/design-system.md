# Cardfolio 设计系统基线

状态：亮暗主题与响应式组件已实现；精确像素仍以当前代码和设计验收为准。
更新日期：2026-08-01

## 1. 原则

- 收藏内容优先：图片和卡片名称是视觉主角。
- 低干扰：常用操作清晰，危险操作不抢占主流程。
- 状态可见：加载、保存、离线、失败和不可用均有明确反馈。
- 可访问：不只依赖颜色表达状态，支持屏幕阅读器和字体缩放。
- 一处定义：颜色、排版、间距、圆角、阴影和动效只通过主题令牌使用。

## 2. 令牌命名

实现时采用语义令牌，不直接在页面写颜色值：

| 类别 | 令牌示例 | 用途 |
|---|---|---|
| 颜色 | `colorPrimary`、`colorSurface`、`colorError` | 品牌、容器、错误 |
| 文本 | `textPrimary`、`textSecondary`、`textOnPrimary` | 文本层级 |
| 间距 | `spaceXs`、`spaceSm`、`spaceMd`、`spaceLg` | 布局与组件间距 |
| 圆角 | `radiusSm`、`radiusMd`、`radiusLg` | 输入、卡片、弹层 |
| 排版 | `display`、`title`、`body`、`label` | 字体层级 |
| 动效 | `motionFast`、`motionStandard` | 状态切换与导航 |

精确值必须从 Figma 变量或经设计确认的交付表生成。未提取前只允许使用 Flutter 主题的集中默认值，不允许页面散落魔法数。

## 3. 核心组件

- `AppShell`：五个固定主入口；手机为底部导航、宽屏为侧边导航，拍摄入口与其他入口保持统一。
- `CardTile`：封面、名称、辅助信息、点击态和图片缺失态。
- `PrimaryButton` / `SecondaryButton` / `DangerButton`：按钮语义明确，保存中禁用重复提交。
- `FormField`：标签、提示、输入、错误文本和字符约束。
- `EmptyState`：说明当前状态并提供一个主操作。
- `InlineError`：字段级或内容级可恢复错误。
- `BlockingError`：数据库无法打开等阻断错误，提供重试和诊断入口。
- `StatusBadge`：离线、待同步、已删除等状态，文字与图形同时表达。

## 4. 内容规范

- 使用简体中文，动词放在操作文案前部。
- 错误文案说明发生了什么和用户能做什么，不展示 SQL、绝对路径或异常栈。
- 阶段性能力统一使用“后续开放”，同时禁用交互。
- 删除操作区分“移入回收站”和“永久删除”。
- 金额显示货币符号和两位小数，存储仍以最小货币单位整数为准。

## 5. 可访问性

- 正文与背景、关键图标与背景满足 WCAG 2.1 AA 对比度。
- 所有图标按钮提供语义标签；装饰图片从语义树排除。
- 不把滑动手势作为唯一操作方式。
- 表单错误通过文本和语义公告表达，并把焦点移至首个错误字段。
- 减少动态效果设置开启时，取消非必要位移和缩放动画。

## 6. 暗色模式与响应式布局

- 亮色使用暖米白表面、深绿主色和克制暖橙；暗色使用墨绿黑背景、深灰绿表面和低饱和浅绿。
- `AppPalette` 和 `AppTokens` 通过 ThemeExtension 集中提供语义颜色、间距、圆角、阴影和动效。
- 用户可跟随系统或手动选择亮/暗主题，偏好持久化到 `app-state.json`。
- 页面内容受最大宽度约束；宽屏使用 NavigationRail，避免卡片和表单无限拉伸。
- 当前发布前仍需完成所有核心页面的 WCAG 对比度、200% 字体、减少动画和图片占位设备验收。
