## 1. 目的

本文定义 Figma 与 Flutter 实现之间的交付边界。PRD 决定产品行为，Figma 决定已覆盖页面的视觉与交互表达，Feature 文档决定当前迭代范围。三者冲突时不得自行猜测，按“业务规则 > 已确认 Feature 范围 > 视觉表达”处理，并在评审中记录差异。

## 3. Feature 001 历史映射

以下内容记录 M0/Feature 001 首次切片边界，不代表当前 App 能力。相机、首页、统计、我的、
套卡和批量录入已在后续 Feature 中实现；OCR 当前不可用状态见[已知问题](../known-issues.md)。

Feature 001 只实现收藏、拍摄入口、新建卡片、卡片详情和五入口导航骨架：

- 收藏页支持空状态、卡片列表、加载、失败和图片缺失状态。
- 拍摄入口仅“从相册导入”可用；相机、连续拍摄、套卡拍摄明确显示阶段性不可用。
- 相册选择成功后直接进入新建卡片，跳过“05 图片裁切与增强”。
- 新建卡片支持一张正面图、必填名称和 PRD 已列出的可选字段。
- 保存成功进入卡片详情；取消或返回不得产生数据库记录。
- 首页、统计、我的保留导航位置，但使用明确的阶段状态，不能伪装成可用功能。

## 4. 设计提取限制

本轮 Figma MCP 调用额度已达到 Starter 套餐上限，无法可靠导出精确变量与截图。因此：

- 本文不填写未经工具验证的颜色、字号、间距和圆角数值。
- 开始 UI 实现前，必须对目标节点重新执行设计上下文提取，并把实际值写入 Flutter 主题令牌。
- 若仍无法提取，由设计人员在 Figma Dev Mode 提供变量表、字体信息、组件状态和切图；未完成前不得声称“像素级还原”。
- 页面结构、节点 ID 和流程映射可以作为当前开发输入。

## 5. 资产交付规则

- 图标优先使用统一图标库；品牌或专有图形从 Figma 导出 SVG。
- 位图按显示场景提供 1×、2×、3× 或足够分辨率的原图，禁止截图代替正式资产。
- 文件名使用小写蛇形命名，例如 `empty_library.png`。
- 资产进入 `assets/` 前需确认版权、透明背景、色彩模式和暗色模式适用性。
- 设计中的示例卡片图片仅作占位，不进入生产包，除非已明确授权。

## 6. 状态交付清单

每个功能页面在进入开发前至少覆盖：

- 默认、加载、空、成功、失败；
- 禁用、按下、聚焦和表单错误；
- 图片缺失、长文本、超大字体、键盘弹出；
- Android 返回键与 iOS 返回手势；
- 权限拒绝、系统选择器取消和保存失败。

## 7. 视觉验收

UI 合并前逐项核对：

1. 目标节点、画板和原型连接正确；
2. 布局在 360、393、430 宽度无溢出；
3. 系统字体放大至 200% 后主要任务可完成；
4. 色彩、字号、间距、圆角与提取后的设计令牌一致；
5. 点击区域不小于 48 × 48 逻辑像素；
6. 交互状态与本文及 Feature 验收文档一致；
7. 视觉差异已记录并得到产品与设计确认。
