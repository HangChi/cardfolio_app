# 卡迹应用标识与拍摄流程调整设计

## 目标

统一应用对外显示名称与品牌图标，移除重复的入手成本入口，并把单卡拍摄调整为可在同一建卡流程中持续添加多张照片、按需编辑的体验。已有卡片和批量建卡中的拍摄入口也采用相同的主动编辑规则。

## 应用标识

- Android、iOS、macOS、Windows、Linux 和 Web 的用户可见名称统一为“卡迹”。
- 包名、Bundle Identifier、二进制名称和 Dart package 名保持不变，避免影响升级、数据库目录和平台工程引用。
- 启动器图标沿用现有原型的品牌语言：深绿色圆角底、白色“卡”字与简化交通卡线条。各平台使用同一主图形，并输出平台要求的尺寸和格式。

## 入手成本入口

- 删除卡片详情页中与“编辑资料”指向同一路由的“记录入手成本”按钮。
- “编辑资料”页面中的入手成本字段继续保留，现有数据模型和保存逻辑不变。

## 单卡拍摄与编辑

- 拍摄首页仅保留一个单卡入口“拍摄单张卡”，删除“单卡多图连拍”。
- 用户拍摄第一张照片后直接进入新建卡片编辑页；需要时再点击图片编辑。
- 新建卡片编辑页的“添加图片”统一弹出来源选择，可选择拍摄或从相册导入。
- 每次拍摄确认后把原图加入当前草稿。用户可重复添加，直到现有单卡 20 张上限。
- 用户取消相机时保留当前草稿；取消主动裁剪时保留编辑前图片。
- 相册导入保持现有多选能力和手动进入图片编辑器的方式，不强制逐张裁切。

## 已有卡片与批量建卡

- 已有卡片详情的“添加图片”也统一提供拍摄和相册两种来源。
- 拍摄所得图片先按原图保存；用户主动编辑后才同时持久化原图及派生图。
- 批量建卡的正面、背面拍摄直接进入草稿，并提供独立“编辑”操作。

## 数据流

1. 相机适配器返回临时原图路径。
2. 图片编辑器以原图路径初始化，生成派生图。
3. 新建卡片将原图和派生图保存在草稿中，最终保存时交给现有图片仓库。
4. 已有卡片直接构造追加图片请求，同时提供原图和派生图路径。
5. 仓库继续负责复制到受管目录、写入数据库及失败清理。
