# Feature 005 购买记录与累计花费设计

日期：2026-07-28

## 目标与边界

在现有卡片藏品和套卡模型上增加独立购买账本。购买是累计花费的唯一事实来源；购买项目只负责对象关系与分摊归因；调整只追加、不改写历史。Feature 005 交付可信账本与基础汇总，图表、主币种偏好和自动汇率属于 Feature 006。

## 方案选择

采用三表关系模型：`purchases` 保存付款事实，`purchase_items` 保存卡片/套卡目标与可选分摊，`exchange_rates` 保存精确历史比率。购买项目使用类型 + 目标 ID，并额外保存名称快照；不对目标建立外键，从而在 Feature 007 永久删除目标后仍保留财务审计。购买与项目在单个事务内写入。

普通购买的 `amountMinor` 表示商品金额，默认累计为商品 + 运费 + 手续费。费用开关只改变查询口径。分摊启用时必须覆盖所有目标且合计等于默认累计，但汇总永远不读取分摊，因此 AC-P0-006 的 500 整套购买只累计 500。

退款通过独立购买行表达：`adjustmentOfId` 引用普通购买，金额为负，币种继承原单，费用为零，目标通过原单追溯。这样历史、对象归因和累计都可重建。

## 金额与多币种

持久化只使用最小货币单位整数。输入解析按 ISO 常见小数位映射处理，未知三位币种默认两位，不使用二进制浮点。汇率用正整数分子/分母表达一个 base 最小单位到 quote 最小单位的转换，并保留日期、来源与获取时间。

基础汇总按原币种返回有序分组。只有所有金额都有完整有效换算信息时，后续统计层才可显示单一主币种总额；缺失汇率必须保留分组，不猜测、不使用 1:1。

## 组件边界

- `purchases/domain`：金额格式、请求规范化、不变量、读模型和仓储接口。
- `purchases/data/local`：购买事务、响应式历史、汇总、候选对象及汇率写入。
- `purchases/data`：幂等、调整校验、UTC/ID 协调与安全错误映射。
- `purchases/presentation`：历史与汇总页、购买表单、退款入口。
- 既有 `organization` 查询只增加按原币种成本排序，不承担账本写入。

## UI 方向

“我的”页增加购买记录入口。购买页顶部使用按币种分开的账本条，费用口径以带文字的开关表达；历史使用正负号与“购买/退款”文字而非只依赖颜色。表单按基本金额、来源、目标、分摊四区组织，目标分卡片与套卡展示。所有长内容和 200% 字体允许滚动与换行。

## 错误与测试

输入/关系错误使用 `PurchaseValidationFailure`；数据库读写映射为现有安全失败类型。自动化覆盖领域边界、真实 SQLite 事务、v4→v5 数据迁移、幂等、退款、删除审计、多币种分组、500 分摊夹具、仓储、Widget 和成本排序。模拟器、重启、窄屏与读屏由用户按手动步骤执行。
