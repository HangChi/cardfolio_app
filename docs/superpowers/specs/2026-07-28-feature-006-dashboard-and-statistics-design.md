# Feature 006 首页与统计查询设计

日期：2026-07-28

## 目标与边界

在现有卡片、套卡、标签和购买事实之上提供只读首页摘要与多维统计。统计不新增事实表、不持久化聚合结果，任何数字都能从活跃源记录重建。Feature 006 只实现本地查询、展示和下钻；汇率换算、保存统计筛选、回收站与同步不在本次范围。

## 口径

- 实体卡总量：活跃藏品实例 `quantity` 之和。
- 款式总量：至少有一个活跃藏品实例的活跃款式去重数。
- 套卡数：活跃套卡数；已集齐数沿用 BR-SET，仅统计总数已知且必需成员全部拥有的套卡。
- 本月新增：按设备本地自然月统计新建藏品实例的 `quantity` 之和，月界线转换为 UTC 后查询。
- 累计花费：沿用 BR-COST，按原币种分别累计；默认包含运费和手续费，退款使用负向调整。
- 最近录入：按藏品创建时间倒序稳定排序，最多 5 项。
- 即将集齐：总数已知、必需成员仅缺 1 款的套卡，按完成度和更新时间排序，最多 5 项。
- 待补资料：活跃款式 `needsCompletion = true` 对应的藏品，最多 5 项。
- 时间、城市、机构、类型、标签分布以实体数量为值。多标签为非互斥维度，因此各桶之和可大于总量。
- 套卡状态分布以套卡数量为值，分为已集齐、差 1 款、未集齐、总数未知。
- 成本趋势按购买发生自然月和原币种分组，不伪造跨币种总额。

## 架构

新增 `dashboard` feature，分为领域模型、只读仓储、Drift 聚合扩展、Riverpod provider 和两个页面。数据库扩展监听卡片、套卡、标签、购买相关表，变化后重新执行有限字段聚合；结果只包含领域对象，不泄露 Drift 行或 SQL。

统计桶携带 `CardLibraryQuery` 下钻条件。现有收藏查询模型增加机构和套卡状态条件，统计页点击桶时直接替换同一个 `cardLibraryQueryProvider` 并进入 `/library`，从结构上保证图表与列表共享条件语义。

## 页面与状态

首页使用摘要卡片、成本分币种列表和三个行动区；无数据时提供“添加第一张卡片”入口。统计页按维度切换展示桶列表，空维度显示可行动空状态；成本趋势独立按月和币种展示。两页都有加载、可重试错误和可滚动布局，点击区域使用 Material 标准组件。

## 错误与性能

读取异常由仓储映射为不暴露内部信息的 `DatabaseUnavailableFailure`。查询只选择聚合所需字段，最近项在领域层限量；固定 10,000 款式数据集使用无设备数据库测试记录耗时，门槛沿用 NFR-PERF-001 的 P95 1,200ms 上限。

## 测试

先用领域测试锁定月份边界、状态和下钻条件；再用内存 SQLite 测试软删除、重复数量、套卡口径、多币种和响应式更新；最后用 fake repository 做首页、统计、空/错/加载和下钻 Widget 测试。自动化仅运行 `flutter test` 与 `flutter analyze`，设备布局和返回行为由人工步骤验收。
