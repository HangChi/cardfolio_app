# Feature 004 标签、系列与筛选设计

日期：2026-07-28

## 目标与边界

在现有卡片款式、藏品实例和套卡模型上增加独立的整理聚合，使用户可以用标签、系列和自定义字段组织收藏，并以响应式查询完成搜索、筛选和稳定排序。Feature 004 交付 P0 整理能力；保存筛选属于 FR-SCH-004 P1，入手成本排序依赖 Feature 005，均不在本次实现。

## 方案选择

标签关联 `CardDefinition`，表示对“款式”的轻量分类。同一款式可拥有多个标签；标签规范化名称在活跃标签中唯一。合并在单个事务内把来源标签的全部款式关系补到目标标签，再软删除来源标签。删除标签不删除卡片。

系列通过两张关系表分别关联 `CardDefinition` 与 `CardSet`。一个对象可以属于多个系列，系列不计算完成度。这样既避免多态外键失去完整性，也让卡片和套卡关系都能使用真实外键与索引。

自定义字段定义和值分离，P0 作用域固定为卡片款式，支持文本、数字和日期。值表使用独立类型列，写入时由领域与数据库双重校验。已有值时不允许改变字段类型；删除前展示影响数量并软删除定义，既有值保留给后续恢复/导出。

## 搜索语义

- 搜索词去首尾空白后，对名称、编号、城市、机构、备注和活跃标签做大小写不敏感的包含匹配；中文按原文本匹配，不做错误的空格分词或拼音猜测。
- 类型、城市、发行年份、套卡关系、重复状态、待补全状态与标签组之间使用 AND。
- 标签组可选择“满足任一（OR）”或“满足全部（AND）”；空标签组不参与筛选。
- 套卡状态在本切片冻结为“全部 / 已加入套卡 / 未加入套卡”。
- 重复按同一款式全部活跃藏品 `quantity` 之和大于 1 判断。
- 排序支持创建时间、发行时间、入手时间和名称；发行/入手时间空值始终置后，最终以藏品 ID 作为稳定兜底。入手成本留给 Feature 005。
- 输入防抖 250ms；查询期间保留明确加载状态。10,000 款式主机数据库基准要求查询本身小于 300ms。

## 组件边界

- 领域层：标签、系列、自定义字段、卡片整理快照、筛选条件、排序和影响预览。
- 数据层：schema v4、关系索引、事务写入、响应式查询和性能基准。
- 仓储层：请求规范化、UTC/版本协调、幂等关系写入和安全错误映射。
- 展示层：收藏页三视图、搜索/筛选/排序、系列表单与详情、整理管理页、卡片整理编辑页。

## 数据流

收藏页持有会话级 `CardLibraryQuery`。搜索文本经 250ms 防抖后与筛选、排序一起传入仓储，仓储创建 Drift 响应式查询，任一卡片、标签、套卡关系或整理字段变化都会刷新结果。卡片详情的“整理信息”读取 `CardOrganizationDetail`，编辑时一次提交元数据、标签、系列和自定义字段值。

标签合并、标签删除、字段删除均先查询 `ChangeImpact`，用户确认后执行单个数据库事务。系列成员保存使用集合差异，在同一事务内添加缺失关系并移除取消关系。

## UI 方向

沿用现有 Cardfolio 米色表面、深绿主操作和橙色提醒令牌，不引入新的视觉系统。收藏页的识别点是搜索框下方的“筛选书签条”：只显示当前有效条件，标签 AND/OR 用清晰文字表达而非颜色。卡片、套卡、系列作为同级分页；系列详情使用双区成员清单，分别呈现卡片与套卡。

管理页从“我的”进入，以“标签 / 自定义字段”两个分区提供创建、重命名、合并、删除及影响预览。卡片详情的整理区显示标签胶囊、系列名称、自定义字段和值；空状态直接提供“整理这张卡”操作。

## 错误与测试

可预期输入、重复名称、类型不匹配和关系冲突使用 `OrganizationValidationFailure`；数据库写失败使用 `PersistenceFailure`；读取失败使用 `DatabaseUnavailableFailure`。自动化覆盖纯领域规则、真实 SQLite、v3→v4 数据迁移、事务回滚、仓储、Riverpod/Widget、组合查询和 10,000 款式基准。模拟器、真实设备重启、系统字体和读屏由用户按手动步骤执行。
