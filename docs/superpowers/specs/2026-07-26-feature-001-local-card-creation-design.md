# Feature 001：本地创建卡片闭环设计

日期：2026-07-26
状态：已确认
关联 PRD：[卡迹 App PRD v1.0](../../product/卡迹App_PRD_v1.0.md)

## 1. 目标

在不登录、无网络的情况下，用户可以从系统相册选择一张图片，填写卡片名称和可选资料，事务性保存卡片，在收藏列表和详情页查看，并在 App 重启后继续访问。

首轮验收以 Android 模拟器或真机为准；Flutter 代码、数据层和平台插件配置保持 iOS 兼容，iOS 构建与真机验证在 macOS 环境补充。

## 2. 范围

### 2.1 范围内

- 首次启动与空收藏状态。
- 五入口主导航骨架。
- 收藏列表。
- 拍摄入口。
- 从系统相册选择单张图片。
- 新建卡片表单。
- 卡片本地持久化。
- 卡片详情。
- App 重启后的数据恢复。
- 名称校验、取消选图、保存失败、重复点击保存等失败和边界状态。

### 2.2 范围外

- 相机拍摄。
- 自动边缘识别、裁切、透视校正、图片增强和模板。
- 连续拍摄与批量导入。
- 多图、背面图和封面管理。
- 套卡、系列、标签和自定义字段。
- 购买记录、统计、回收站、导入导出。
- 账号、云同步和冲突处理。

Figma 中的“05 图片裁切与增强”不进入 Feature 001。从相册选图后直接进入“06 新建卡片”。

## 3. 架构决策

采用功能优先的分层架构：

```text
lib/
├── app/                  # App、路由、主题与主导航
├── core/                 # 通用错误、ID、时间与文件能力
└── features/
    └── cards/
        ├── domain/       # 领域实体、仓储契约和业务规则
        ├── data/         # Drift 表、DAO、文件存储与仓储实现
        └── presentation/ # 页面、状态和可复用 UI
```

技术基线：

- Riverpod：依赖注入和页面状态；首期手写 Provider/Notifier，不启用 Riverpod 代码生成。
- Drift/SQLite：关系型本地数据库、事务、响应式查询和版本化迁移。
- go_router：声明式路由与主导航壳。
- image_picker：系统相册选择器与 Android 丢失数据恢复。
- uuid：本地生成稳定 ID，为离线创建和未来同步预留。

UI 不直接访问 Drift、文件系统或平台插件。页面只依赖状态控制器；控制器只依赖仓储和图片选择契约。

## 4. 页面与组件

### 4.1 AppShell

保留 Figma 的五个主入口：首页、收藏、拍摄、统计、我的。

- 收藏与拍摄在 Feature 001 中可用。
- 首页、统计和我的显示明确的阶段性占位状态。
- 不提供看似可用但没有行为的入口。

### 4.2 收藏列表

- 启动后订阅 `CardSummary` 数据流。
- 空状态提供“从相册导入”主操作。
- 非空状态展示卡片图片、名称及可用的摘要字段。
- 点击卡片进入详情。

### 4.3 拍摄入口

保留四种录入方式的视觉结构：

- 从相册导入：可用。
- 拍摄单张卡、连续拍摄、创建套卡并拍摄：标记为后续开放且不可执行。

### 4.4 新建卡片

- 显示所选图片预览。
- 名称必填。
- 城市、发行方、发行时间、编号、备注可选。
- 保存中禁用返回冲突操作和重复提交。
- 用户离开未保存页面时不产生数据库记录。

### 4.5 卡片详情

- 根据卡片 ID 读取 `CardDetail`。
- 展示正面图片、名称和已填写的资料。
- 记录不存在时提示并返回收藏列表。

## 5. 领域与数据模型

从首个版本开始遵循 PRD 的核心三层实体，避免后续因多图、重复藏品和套卡功能拆分临时大表。

### 5.1 CardDefinition

描述一种卡片款式。

- `id`
- `name`
- `city`
- `issuer`
- `issuedAt`
- `code`
- `notes`
- `createdAt`
- `updatedAt`

### 5.2 CardItem

描述用户实际持有的藏品。

- `id`
- `definitionId`
- `quantity`，Feature 001 固定默认为 1
- `createdAt`
- `updatedAt`
- `deletedAt`

### 5.3 CardImage

描述受 App 管理的图片。

- `id`
- `cardItemId`
- `kind`，Feature 001 仅使用 `front`
- `relativePath`
- `sortOrder`
- `checksum`
- `createdAt`

所有 ID 使用 UUID。数据库路径不保存设备绝对路径，只保存相对于 App 图片根目录的路径。

### 5.4 查询模型

- `CardSummary`：收藏列表所需的稳定只读模型。
- `CardDetail`：详情页所需的组合只读模型。

查询模型隔离 UI 与数据库表结构，使迁移和查询优化不影响页面契约。

## 6. 数据流

### 6.1 启动

1. 初始化 App 私有图片目录。
2. 打开 Drift 数据库。
3. 执行 schema 创建或迁移。
4. 清理没有数据库引用的受管理图片。
5. 收藏列表开始订阅卡片摘要。

数据库打开失败时进入阻断错误页，不静默删除或重建用户数据库。

### 6.2 创建卡片

1. 用户从空状态或拍摄入口触发相册选择。
2. 系统选择器返回 `XFile`；取消则结束流程。
3. 控制器验证图片可读性并建立内存草稿。
4. 跳转到新建卡片页面。
5. 用户填写资料并保存。
6. 控制器校验名称，进入保存状态并阻止重复提交。
7. 仓储使用草稿 UUID 生成确定的相对路径，将图片复制到 App 私有目录并计算校验值。
8. Drift 事务写入 `CardDefinition`、`CardItem` 和 `CardImage`。
9. 事务失败时补偿删除本次复制文件；成功时文件已经位于最终路径。
10. 返回卡片 ID并进入详情。
11. 收藏列表的数据流自动发出新结果。

### 6.3 重启恢复

App 重启后从 SQLite 重新生成 `CardSummary` 和 `CardDetail`，图片通过相对路径解析到当前 App 私有目录，不依赖系统相册原始文件继续存在。

## 7. 错误处理与一致性

- 取消选图：不提示错误，不创建草稿。
- 相册访问被拒绝：说明用途并提供重试；需要时引导系统设置。
- 图片不可读取：阻止进入表单并提示重新选择。
- 名称为空：字段级校验，不调用仓储。
- 重复保存：控制器保存锁加固定草稿 UUID/数据库唯一约束双重防护。
- 文件复制失败：不启动数据库事务。
- 数据库事务失败：删除本次复制文件，不留下半条记录。
- 进程在文件复制后终止：下次启动清理无数据库引用的受管理文件。
- 保存已提交但导航失败：不回滚成功数据，用户返回收藏列表后仍可访问。
- 数据库打开失败：保留原文件，展示重试和诊断信息，不自动清库。
- UI 只显示稳定的用户错误文案；底层异常保留给日志和测试，不直接暴露路径或 SQL 信息。

## 8. 测试策略

### 8.1 单元测试

- 名称标准化和空名称校验。
- 创建草稿状态变化。
- 保存期间重复提交只触发一次仓储调用。
- 仓储错误映射为稳定失败类型。
- 相册取消不进入创建流程。

### 8.2 数据层集成测试

- 内存 Drift 数据库创建三类关联记录。
- 事务中任一步失败时三张表均无残留。
- 卡片摘要和详情组合查询正确。
- 数据库关闭并重新打开后记录仍存在。
- UUID 唯一约束阻止重复记录。
- schema v1 与迁移基线可验证。

### 8.3 文件存储测试

- 图片复制到受管理目录并计算校验值。
- 数据库失败后补偿删除。
- 启动清理只删除未被数据库引用的受管理文件。
- 相对路径在重启后可以解析。

### 8.4 Widget 测试

- 空收藏状态。
- 新建表单名称错误。
- 保存中按钮禁用和加载状态。
- 保存成功进入详情。
- 收藏列表显示新卡。
- 详情缺失状态。

### 8.5 Android 验收

- 从系统相册选择图片并完成保存。
- 取消系统选择器后无脏数据。
- 快速连续点击保存只创建一张卡。
- 强制结束并重启 App 后卡片与图片仍存在。
- 拒绝权限或平台选择器异常时可以恢复。
