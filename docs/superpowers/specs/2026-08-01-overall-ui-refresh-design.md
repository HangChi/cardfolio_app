# Cardfolio 整体 UI 优化设计

日期：2026-08-01  
状态：已确认

## 1. 背景与目标

Cardfolio 已具备首页、收藏、拍摄、统计、我的，以及卡片、套卡、整理、备份和同步等完整业务界面。本轮不改变数据库、仓储、同步协议或核心业务规则，而是在现有米白、深绿、橙色品牌基础上，系统性提升视觉一致性、信息层级、触控体验、响应式适配和可访问性，并同时交付完整亮色与暗色主题。

成功标准：

- 核心页面共享统一的语义颜色、排版、间距、圆角、阴影、图标和动效令牌。
- 首页、收藏、拍摄、统计、我的五个主入口具有一致但可区分的内容层级。
- 高频表单、详情页、空状态、加载状态和错误状态具有统一反馈语言。
- 手机与宽屏设备均能自然使用，不出现水平溢出或过度拉伸。
- 亮色与暗色主题分别满足可读性和状态辨识要求。
- 所有核心交互保留现有业务行为，并通过现有测试与新增 UI 测试验证。

## 2. 已选设计方向

采用“品牌精修＋轻度收藏档案感”。保留温暖纸张、深绿主色和橙色强调，避免高强度玻璃拟态、霓虹、复杂纹理及大幅品牌重塑。收藏档案感通过编号、标签、分组、稳定图片比例和清晰元数据层级表达，不通过装饰性噪点或仿古滤镜表达。

未采用的方向：

- 纯博物馆档案风：辨识度高，但会削弱现有亲和感。
- 暗色沉浸优先：更适合影音或专业工具，与 Cardfolio 的温暖收藏体验不完全匹配。

## 3. 设计系统

### 3.1 颜色与主题

亮色主题延续柔和米白背景、暖白表面、深绿主色和克制橙色强调。暗色主题采用墨绿色黑背景、深灰绿表面、低饱和浅绿主色和暖橙强调，不对亮色值进行机械反转。

颜色全部通过语义令牌提供，包括：页面背景、基础表面、抬升表面、主文字、次文字、弱文字、描边、主色、次强调、成功、警告、错误以及各自容器色。页面组件不得新增未经主题管理的业务颜色。

正文与背景对比度目标不低于 4.5:1，大号文字和主要图形不低于 3:1。状态信息同时使用文字或图标，不能只依赖颜色。

### 3.2 排版

继续使用设备可用的中文无衬线字体，以 `Noto Sans SC`、`Microsoft YaHei` 和系统字体作为回退，避免引入依赖网络的字体资源。

排版层级统一为展示标题、页面标题、分区标题、卡片标题、正文、辅助文字和标签。页面标题与关键数字提高字重；正文提高行高；金额、数量、日期和进度数字启用等宽数字特性，减少变化时的视觉抖动。

### 3.3 空间、形状与层级

布局使用 4/8 逻辑像素节奏。页面边距、分区间距、组件内边距和控件间距从统一令牌获取。圆角保持小、中、大和胶囊四档；阴影只用于表达层级，限制为无、轻、中三档，暗色主题以描边和表面明度差补充层级。

卡片图片使用稳定宽高比和一致圆角。缺图状态使用主题驱动的矢量占位构图，不使用表情符号或随机图标。

### 3.4 动效

交互反馈采用 180–260ms 的轻量淡入、颜色或透明度变化，以及少量不引发布局回流的位移。动效只用于解释状态变化或导航层级，不作为装饰。系统请求减少动态效果时，取消非必要位移和缩放，仅保留即时或短淡入反馈。

## 4. 信息架构与响应式布局

手机继续使用底部五入口导航：首页、收藏、拍摄、统计、我的。中央拍摄入口保持视觉强调，但继续提供可访问标签和稳定点击区域。

较宽窗口使用左侧 `NavigationRail` 与受限最大宽度内容区，避免在平板和桌面窗口上拉伸手机布局。主内容保持单一滚动容器，固定导航为内容预留安全区。

各入口重点如下：

- 首页：收藏总览、最近录入、即将集齐和待补资料，建立清晰的概览到任务路径。
- 收藏：搜索、类型切换、筛选、排序、卡片内容和新增操作，确保收藏内容始终是视觉主角。
- 拍摄：聚焦一个主操作，其他录入方式按层级排列并明确状态。
- 统计：突出关键数字、趋势、分布和可下钻入口，图形之外保留文本信息。
- 我的：按账号与同步、收藏整理、数据管理、应用设置分组，危险操作与普通入口分离。

## 5. 组件架构

在核心 UI 层建立可复用组件，页面只负责组合业务内容：

- `AppPageHeader`：页面标题、说明、主次操作和可选统计摘要。
- `AppSection` / `AppSectionHeader`：分区标题、辅助说明与尾部动作。
- `AppSurfaceCard`：统一表面、圆角、描边、阴影和按下反馈。
- `AppMetricCard`：关键数字、变化、辅助说明和语义图标。
- `AppActionTile`：设置与管理入口，统一图标容器、标题、说明和尾部状态。
- `AppStatusBadge`：文字与图形共同表达离线、待完善、进行中、失败等状态。
- `AppEmptyState` / `AppErrorState`：统一插图、说明与单一恢复动作。
- `AppResponsiveScaffold`：负责手机与宽屏导航及内容最大宽度。

现有业务专用组件继续保留。只有在至少两个页面共享同一视觉和行为模式时才抽取，避免为了形式统一而创建无实际价值的抽象。

## 6. 交互、表单与反馈

所有按钮、输入框、筛选项、图标动作和导航入口至少提供 48×48 逻辑像素触控区域，并具备按下、聚焦、禁用和加载状态。图标按钮必须包含语义标签；选择状态需通过图标、文字或形状共同表达。

表单不改变字段、校验和保存逻辑，只优化：

- 相关字段分组与渐进披露；
- 可见标签、帮助文字、字符限制和就近错误；
- 日期、数字、金额等合适的键盘与输入动作；
- 保存期间禁用重复提交，并显示进行中反馈；
- 键盘弹出、底部操作栏和系统安全区之间的布局关系；
- 离开未保存内容时沿用已有确认逻辑。

加载、空数据、无筛选结果、失败、离线、权限拒绝和危险操作均提供清楚说明及可执行的恢复路径。错误信息不暴露异常栈、数据库语句或绝对路径。

## 7. 数据流与边界

本轮仅调整展示层和主题层。页面继续通过现有 Riverpod provider 获取异步状态，通过现有路由执行导航，通过现有控制器和仓储完成业务操作。

组件接收格式化后的展示模型或明确回调，不直接访问数据库、文件系统或远端服务。主题切换读取现有设备设置模型；如该模型缺少主题偏好，只在当前设置边界内添加 `system`、`light`、`dark` 三态，不改变其他持久化协议。

## 8. 错误处理与可访问性

- 异步失败使用页面内错误状态或靠近操作的错误提示，并提供重试或返回动作。
- 破坏性操作继续使用确认弹层，危险按钮使用语义错误色并与主操作空间分离。
- 重要状态变化使用语义公告，不抢夺当前输入焦点。
- 阅读顺序与视觉顺序一致；超大字体下允许文本换行，不把截断作为默认方案。
- 系统字体放大到 200% 后，核心浏览、新建、编辑、保存和恢复任务仍可完成。
- 亮暗主题分别检查文字、图标、边框、禁用态、聚焦态、错误态和弹层遮罩的辨识度。

## 9. 测试与验收

自动化验证包括：

- 主题与令牌单元测试，覆盖亮色、暗色和系统主题选择。
- 响应式导航测试，覆盖手机底部导航与宽屏侧栏。
- 首页、收藏、拍摄、统计、我的的核心组件与状态测试。
- 关键表单、详情、空状态和错误状态的现有回归测试。
- `flutter analyze` 与完整 `flutter test`。

人工或截图验收包括：

- 360、393、430 逻辑像素宽手机，以及平板/桌面宽窗口。
- 亮色与暗色主题。
- 200% 字体缩放、减少动态效果和键盘弹出。
- 加载、空、成功、失败、缺图、长文本、禁用、聚焦和危险确认状态。
- 页面无水平溢出，主要内容不被导航、底部操作栏或系统安全区遮挡。

## 10. 实施范围

优先级依次为：主题与基础组件、响应式应用外壳、五个主入口、高频详情与表单、次级管理页面、视觉与回归验证。允许在触达页面中移除重复样式和散落颜色，但不进行与 UI 目标无关的架构重构。
