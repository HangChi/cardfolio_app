# 图片存储与生命周期

状态：当前实现基线
更新日期：2026-08-01

## 1. 原则

- 用户选中或拍摄的文件复制到 App 私有目录，后续不依赖系统相册原路径。
- 原图不可被裁剪、旋转或增强覆盖；活动编辑结果使用独立派生文件。
- 数据库只保存受管根目录下的相对路径、用途、顺序、封面和校验值。
- 数据库与文件系统跨边界失败必须补偿或形成可重试清理意图。

## 2. 运行目录

应用支持目录下使用 `cardfolio/`：

```text
cardfolio/
├── cardfolio.sqlite
├── app-state.json
├── images/                    # ManagedImageStore 管理的原图/派生图
├── backup-work/               # 启动时重建的备份临时目录
└── image-processing-work/     # 启动时重建的图片编辑临时目录
```

具体文件名使用 UUID，不包含卡名、地址、备注或账号信息。路径解析后必须仍位于受管根目录。

## 3. 录入与编辑

1. 相机或系统相册返回临时文件；取消操作不生成草稿数据。
2. 用户先进入资料页，可继续添加正面、背面和其他用途图片。
3. 保存卡片时，图片复制进受管目录、计算 SHA-256，并在数据库事务中写入相对路径。
4. 用户点击“编辑”后，Android 通过 uCrop、iOS 通过系统照片式裁剪组件完成移动、缩放和旋转。
5. 只有亮度、对比度、清晰度等需要像素处理的调整才进入 isolate 处理器；无调整的 JPEG
   裁剪结果允许直接发布，避免第二次完整解码/编码。
6. `derived_relative_path` 指向当前活动结果；详情优先显示派生图，原图仍用于重置和重新编辑。

当前实现保持裁剪结果的现有像素尺寸，不再统一放大或缩放到 4096px。JPEG 结果使用质量 95；
高像素图片叠加清晰度处理仍可能耗时，必须保持在非 UI isolate 执行。

## 4. 多图规则

- 单藏品最多 20 张活跃图片。
- 用途包括正面、背面、包装、编号、细节和其他。
- 每个藏品最多一张活动封面；删除封面时选择下一张活动图片。
- 详情页使用大图左右滑动，图片下方显示用途、封面状态、页码和统一管理入口，图片上不叠按钮。
- 删除最后一张图片是允许的，卡片回到无图占位状态。

## 5. 删除与恢复

- 软删除卡片保留原图、派生图、标签、集卡册、套卡和成本关系，恢复后完整回归。
- 从图集移除但“保留原图”时写入图片软删除标记，默认查询不展示。
- 硬删图片前查找套卡 `cover_image_id` 和集卡册 `cover_relative_path` 引用并清空。
- 永久删卡先在数据库事务写入所有待删相对路径，再删除元数据；物理文件失败进入
  `file_cleanup_queue`，下次启动继续重试。
- 启动时必须先成功读取数据库引用，才允许执行孤儿文件清理；数据库打不开时不触碰图片。

## 6. 备份与同步

- ZIP 备份包含数据库逻辑快照、所有引用图片、相对路径、大小和 SHA-256。
- 解压时拒绝绝对路径、`..` 路径逃逸、超额条目、异常压缩比和校验失败。
- 同步先上传原图/派生图附件，按 SHA-256 校验，再提交元数据；下载使用临时文件原子发布。

## 7. 设备验收重点

- Android/iOS 相机取消、权限拒绝和进程结果恢复。
- HEIC/高像素图片、连续添加 20 图、裁剪旋转和亮度/对比度。
- 编辑保存耗时、低存储失败、强停重启、原图和派生图可访问。
- 删除封面、删除最后一图、软删除恢复、永久删除和启动清理重试。
