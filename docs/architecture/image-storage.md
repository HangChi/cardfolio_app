# 图片存储与生命周期

状态：M0 基线
日期：2026-07-26
关联需求：FR-IMG-001–007、BR-IMG-001–003、NFR-PERF-003、NFR-CAP-001

## 1. 目标

- 用户选中的图片在 App 私有目录中长期可用，不依赖系统相册原路径。
- 原图与派生图明确分离。
- 数据库与文件系统跨边界失败时不产生用户可见半成品。
- 支持未来导出、同步、空间统计和永久删除。

## 2. 目录

数据库只保存相对路径。建议根目录：

```text
cardfolio/
├── originals/<cardItemId>/<imageId>.<ext>
├── derived/<cardItemId>/<imageId>/<variantKey>.<ext>
├── thumbnails/<cardItemId>/<imageId>.<ext>
├── staging/<operationId>/
└── quarantine/<recoveryId>/
```

- `originals`：用户明确导入或拍摄的原始文件。
- `derived`：裁切、校正、增强和模板结果。
- `thumbnails`：可重建缓存。
- `staging`：尚未完成数据库提交的临时文件。
- `quarantine`：恢复流程发现但无法安全自动处理的文件。

## 3. 导入流程

1. 系统选择器返回用户明确选择的文件。
2. 验证可读性、大小、扩展名和基础媒体类型。
3. 为操作和图片生成 UUID。
4. 复制至 `staging/<operationId>`。
5. 计算 SHA-256、字节数和媒体元数据。
6. 移动到确定的最终相对路径。
7. 数据库事务写入图片及关联实体。
8. 事务失败时删除本操作写入的最终文件。
9. 进程中断遗留文件在下次启动按引用关系恢复或清理。

重复提交使用相同业务幂等 ID 时，先检查既有数据库记录，不覆盖已被正式记录引用的文件。

## 4. 原图与派生图

- 原图默认只读，任何增强生成新文件。
- 派生图记录来源原图、处理版本、参数摘要和校验值。
- 模板或算法升级不原地改变旧派生图；按需生成新 variant。
- 缩略图是可重建缓存，不作为导出一致性的唯一文件。
- 原图默认保留策略在 Feature 002 开始前依据空间测试冻结。

## 5. 文件命名

- 文件名使用 UUID，不包含卡名、城市、备注或用户信息。
- 扩展名根据验证后的媒体类型决定，不盲信原始名称。
- 路径拼接后必须验证仍在配置根目录内。
- 删除接口只接受受控相对路径，不接受任意绝对路径。

## 6. 清理

### 启动恢复

- 扫描超过安全等待时间的 staging 操作；
- 查询数据库引用；
- 未引用且确认属于卡迹根目录的文件可删除；
- 路径异常、校验异常或状态不明的文件移动到 quarantine；
- 清理失败记录日志并在下次启动重试。

### 软删除

- 保留原图、派生图和缩略图；
- 默认列表不展示；
- 导出是否包含回收站内容由导出选项明确说明。

### 永久删除

1. 数据库计算不再被任何活跃或回收站对象引用的文件；
2. 事务记录永久删除意图；
3. 删除文件；
4. 标记清理完成；
5. 失败进入可重试队列，不把业务记录伪装成仍活跃。

## 7. 空间与容量

- 单个藏品至少支持 20 张图片。
- 单次 100 张导入分批复制、校验和提交。
- 12MP 处理不在 UI isolate 连续阻塞超过 100ms。
- 空间页分别展示原图、派生图、缩略图和暂存占用。
- 低存储时停止新写入并保留现有数据，不通过自动删除原图释放空间。

## 8. 测试

- 格式、空文件、不可读文件和路径逃逸；
- 同名文件和重复幂等操作；
- 复制失败、事务失败、移动失败和进程中断；
- 启动孤儿清理不删除被引用文件；
- 软删除与恢复不丢图；
- 永久删除只清理无其他引用文件；
- 导出校验值与实际文件一致；
- Android/iOS 相同输入得到相同领域结果。
