# ADR-007：本地优先同步边界

日期：2026-07-26
状态：Accepted

## 背景

PRD 要求不登录可用、网络不阻塞保存，并在 V1.0 提供可选云同步。过早绑定某个后端会让本地模型和用户成功语义受云服务影响。

## 决策

本地数据库是客户端事实来源。用户写操作在一个本地事务中保存业务变化和持久同步意图；本地事务成功即向用户报告保存成功。同步引擎异步上传、重试和处理冲突。

云服务商、配额和认证实现延迟到 Feature 010，根据 M1–M5 的真实数据规模和隐私要求选型；该延迟不改变本 ADR 的边界。

## 理由

- 满足无网和不登录核心使用。
- 服务端故障不会阻塞收藏操作。
- 同步实现可替换。
- 持久队列、幂等键和冲突副本可自动化测试。

## 后果

- 所有可同步实体从初始 schema 具备 UUID、时间和版本。
- 同步操作具备唯一幂等键。
- 退出账号不自动删除本地数据。
- 删除使用墓碑和保留窗口，不静默覆盖离线修改。
- 服务器不能成为客户端业务规则的唯一实现。

## 冲突默认策略

- 不同字段修改可在契约允许时合并。
- 同一字段并发修改生成冲突副本。
- 删除与修改冲突保留修改内容。
- 二进制图片不做内容级自动合并。

## 未采用

- 云端优先写入：违反离线和本地成功语义。
- 最后写入者无条件覆盖：存在静默数据丢失风险。
- 在 M0 绑定具体 BaaS：缺少容量、成本和区域证据。
