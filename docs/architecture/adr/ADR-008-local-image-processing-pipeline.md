# ADR-008：系统相机入口与本地图片处理管线

日期：2026-07-29
状态：Accepted

## 背景

Feature 009 需要 Android/iOS 相机拍摄、连续录入、相册式裁剪、旋转、
基础增强和模板输出，同时满足原图不可变、离线可用、跨平台一致与 12MP 主线程
阻塞限制。自建原生取景器和云端识别都会显著扩大权限、隐私和维护边界。

## 决策

- 使用 Flutter 官方 `image_picker` 1.2.3 打开系统相机，每次用户点击拍摄时调用一次，并在编辑页逐张追加；
- 使用 MIT 许可的纯 Dart `image` 4.9.1 解码、EXIF 归一化、透视、增强和 JPEG 编码；
- CPU 密集处理通过 `Isolate.run` 在 worker isolate 执行；
- 拍摄不强制进入裁剪；用户在资料页主动打开 `image_cropper` 的平台裁剪界面；
- 原图保存于 `originals/`，当前派生 JPEG 保存于 `derived/`，数据库关联两条相对路径；
- HEIC 可作为不可变原图保存；本地处理器无法解码时明确提示改用 JPEG/PNG，不上传转换。

## 理由

- 系统相机入口复用平台权限和拍摄体验，不引入自建相机生命周期；
- 领域契约隔离 `XFile`、平台异常和具体处理库；
- 同一处理实现覆盖 Android/iOS/桌面自动化，便于确定性测试；
- 纯本地处理不扩大隐私数据流；
- 平台裁剪器不可用时仍保留原图，不阻塞核心建档。

## 后果

- 无自定义实时取景框、闪光灯或焦距控制；
- 12MP 峰值内存、HEIC 与色彩表现必须在目标真机继续验收；
- 当前每张原图只有一张活动派生图；历史编辑通过原图重新生成，而非保存全部版本；
- 工作目录在启动时清空，取消结果不进入草稿，已保存文件由既有生命周期管理。

## 未采用

- 自建 `camera` 取景器：生命周期、权限、设备差异和测试成本更高；
- 云端/模型边缘识别：违反默认本地处理边界并新增隐私、网络与许可风险；
- 原生 OpenCV 双平台实现：自动识别能力更强，但包体和维护成本不符合当前 Beta 范围；
- 覆盖原图：违反 BR-IMG-001，无法可靠撤销或重新生成。
