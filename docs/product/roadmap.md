# 卡迹产品路线图

状态：基线版
日期：2026-07-26
事实来源：[PRD v1.0](./卡迹App_PRD_v1.0.md)

## 1. 路线图目标

卡迹以“可靠的本地收藏闭环”为起点，逐步建立收藏组织、成本统计、图片处理、数据迁移和可选云同步能力。每个里程碑必须产生可独立验收的软件，不以页面完成数量代替用户价值。

## 2. 里程碑

| 里程碑 | 目标 | 功能范围 | 进入条件 | 退出条件 |
|---|---|---|---|---|
| M0 项目基线 | 建立可持续交付方式 | PRD、领域模型、ADR、测试策略、设计交付、CI 约定 | PRD 已评审 | Feature 001 满足 DoR |
| M1 本地卡片闭环 | 完成第一条真实价值路径 | Feature 001、002 | M0 完成 | 相册导入、多图、保存、列表、详情、重启恢复通过 |
| M2 收藏组织 | 让收藏可被组织和查找 | Feature 003、004、007 的软删除部分 | M1 完成 | 套卡、标签、系列、筛选和恢复规则测试全绿 |
| M3 购买与统计 | 建立可信的数量和成本口径 | Feature 005、006 | M2 完成 | 成本可追溯且无重复累计；统计可下钻 |
| M4 图片技术闭环 | 验证高效录入核心竞争力 | Feature 009 | Feature 002 稳定 | 真实卡片样本和目标设备性能达标 |
| M5 数据安全 | 让收藏可迁移、可恢复 | Feature 008、007 永久删除部分 | M1–M3 数据模型稳定 | 导出导入往返一致；失败不修改现有数据 |
| M6 云同步与发布 | 支持长期多设备使用 | Feature 010、正式发布治理 | M5 完成 | V1.0 AC、隐私、安全、监控和商店门禁全部通过 |

## 3. 推荐交付顺序

```text
M0
└── 001 本地创建卡片
    ├── 002 多图与封面
    ├── 003 套卡与完成度
    └── 004 标签、系列与筛选
        ├── 007 回收站
        └── 005 购买与成本
            └── 006 首页与统计
                └── 008 导出导入
                    ├── 009 相机与图片处理
                    └── 010 账号与同步
```

Feature 009 可在 Feature 002 完成后并行开展技术 Spike，但产品化必须以真实样本和性能报告为准。

## 4. 版本范围

### MVP Alpha

- 本地无账号使用。
- 单卡和多图建档。
- 套卡、系列、标签、搜索筛选。
- 购买记录、基础统计。
- 软删除、备份导出。

### MVP Beta

- 相机拍摄。
- 边缘识别、手动四角、透视校正。
- 基础增强、模板和连续录入。
- 大数据量与低存储测试。

### V1.0

- 可选账号和云同步。
- 多设备恢复和冲突副本。
- 完整导入导出、隐私治理、监控和发布流程。

## 5. 路线图变更规则

新增需求必须同时说明：

1. 所属优先级和里程碑；
2. 替代、推迟或删除的既有范围；
3. 对数据模型、隐私、性能和测试的影响；
4. 对 PRD、Feature Spec 和验收矩阵的修改；
5. 是否改变已承诺的退出条件。

未完成以上评估的需求不进入迭代。

## 6. 决策门禁

| 决策 | 最迟时间 | 进入决策所需证据 |
|---|---|---|
| 汇率来源与历史口径 | Feature 005 开始前 | 用户研究、离线需求、费用和授权限制 |
| 原图默认保留策略 | Feature 002 开始前 | 真实图片体积、设备空间测试、用户偏好 |
| 图像处理方案 | Feature 009 产品化前 | Spike 报告、样本准确率、耗时和包体影响 |
| 云服务与配额 | Feature 010 开始前 | 数据规模、成本模型、隐私和区域合规 |
| 冲突自动合并粒度 | Feature 010 契约冻结前 | 实体版本模型和多设备冲突测试 |
