# 卡迹业务规则汇总

状态：当前实现口径
更新日期：2026-08-01

## 1. 卡片与数量

- 新建卡片 UI 要求名称、城市和大于 0 的持有数量；图片和其余资料可后补。
- 空历史数据或旧数据名称在展示层可回退为“未命名卡片”，避免迁移破坏既有记录。
- 总卡片数是全部未删除实体 `quantity` 之和；不同款式数按 `definition_id` 去重。
- 重复卡条件：同一款式下全部未删除实体的 `quantity` 总和大于 1。
- 回收站实体不参与收藏、筛选、集卡册可见成员、统计、套卡拥有量和消费。

## 2. 套卡与集卡册

- 套卡表示有明确成员的收集目标；同款重复只增加重复张数，不提高完成度分子。
- 已知整套张数时，完成度 = 已拥有必需款式数 / 整套张数；未知时不显示百分比或已集齐。
- 套卡成员是应收集款式。删除实体卡只把拥有数量降为零，不删除成员定义。
- 集卡册是宽泛文件夹，可同时包含卡片款式和套卡，自身不使用标签、不计算完成度。
- 集卡册保存时保留因回收站而暂时隐藏的成员关系，恢复后自动重新显示。

## 3. 标签、字段与筛选

- 标签和自定义字段名称按规范化名称唯一；保留字段不会在编辑时重复创建。
- 删除标签/字段前展示影响数量；删除定义只清理关系或值，不删除卡片。
- 城市统计和筛选归一到市级；中国地址可保存省/市/县区，县区可省略，国外可手输。
- 本月筛选使用 `acquired_at`，按设备本地自然月转换为 UTC 的起始包含、结束不包含区间。
- 常用筛选 UI 与入手成本排序已移除；旧 JSON 字段继续兼容读取。

## 4. 成本

- 当前用户入口固定人民币，持久化为分；金额输入最多两位小数且不得为负。
- 卡片金额和运费都为空或为 0 时不保留该卡的内部成本记录。
- 每张卡使用稳定的内部购买 ID 更新同一条成本，编辑不会重复累计。
- `purchases`/`purchase_items` 仍是统计事实来源，用于兼容旧购买、退款、备份和同步。
- 首页总花费是全部活跃收藏的全时期人民币净消费；删除卡片后排除，恢复后重新计入。
- 消费趋势中，卡片快捷成本优先使用入手日期，无入手日期时使用账本日期；历史普通购买和
  退款使用账本日期。
- 发售价是资料，不计入实际消费。

## 5. 图片

- 相机/相册取消不生成数据；拍照后直接进入资料页，不强制裁剪。
- 原图不可被编辑结果覆盖；裁剪、旋转或增强结果保存为活动派生图。
- 单卡最多 20 张活跃图片，可无图；每卡最多一张活动封面。
- 删除封面时自动选择下一张；删除最后一图后显示无图占位。
- 硬删图片或永久删卡前清理套卡和集卡册封面引用；物理文件失败进入持久队列。

## 6. 删除、备份与同步

- 软删除保留图片、标签、集卡册、自定义字段、套卡和成本关系，恢复后完整回归。
- 永久删除需二次确认；先持久化文件清理意图，再按业务顺序删除依赖数据。
- ZIP 备份必须校验版本、条目、路径、大小、压缩比和 SHA-256；校验失败不修改现有收藏。
- 本地写入先成功，云端不是本地成功前提；同步操作有稳定幂等 ID 和指数退避。
- 不同字段可三方合并；同字段或删除/修改冲突保留双方副本，不静默覆盖。
- 退出账号默认保留本地；删除账号时用户独立选择是否删除本地副本。
